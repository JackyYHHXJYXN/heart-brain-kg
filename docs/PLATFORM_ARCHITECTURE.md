# 平台架构与分阶段任务（技术文档）

2026-11-05 起草，用户已批准总体方案。本文件只写技术；增长、营销、合作等策略不放公开仓库。
与 `CLAUDE.md` 冲突时以 `CLAUDE.md` 为准。现有引擎的数据格式见 `docs/ARCHITECTURE.md`，迁移完成前继续有效。

## 1. 核心原则

- 所有知识图谱共用**一个概念库**。每个领域图谱只是概念库上的一个“视图”（选哪些概念、按什么顺序讲），不是独立数据。同一个概念（如高血压）全站只写一次、只审一次。
- **事实只存在于断言里**。页面只组装概念和断言，不写新事实。
- **每条断言至少 1 个来源**，记录版本年份和原文定位；页面上的数字必须能在原文关键句中找到，校验脚本自动比对，找不到就不能发布。
- **公众层只写读者能做的事**（识别、呼救、不要做什么、到医院后会发生什么、可以问医生什么）。药物剂量、医院质控指标不进公众页，只留在私有专业库。
- 运行时不加载任何第三方脚本和字体；只用系统字体；必须在中国大陆和微信内可用。统计按第 13 节，只做匿名汇总。

## 2. 五层结构

| 层 | 内容 | 位置 |
|---|---|---|
| 基础层 | 来源注册表、地区设置、术语表（简繁英）、审核记录 | `content/sources/`、`content/regions/`、`content/i18n/`、`content/reviews/`；整段原文摘录放本机私有目录（不进 Git） |
| 概念层 | 概念、断言、关系（全站一份） | `content/concepts/` |
| 视图层 | 14 个领域图谱、2 个交叉视角、站点级急救中心 | `content/graphs/`、`content/views/` |
| 呈现层 | 三语静态页、链接封面、浏览器内生成的分享卡片、开放 JSON | 构建产物 → GitHub Pages |
| 分发层 | 各平台 | 不在仓库 |

## 3. 记录类型

| 记录 | 必填字段 | 规则 |
|---|---|---|
| 概念 | `uid`、`type`、`home`（主页所属领域）、各语言名称、可选 `codes` | `uid` 登记在 `tools/uids.lock.json` 后不改不删；下线写 `retired` 并注明原因 |
| 断言 | `id`、文字（各语言）、`tier`（A/B/C）、`sources`、可选 `regions` | 数字必须出现在来源关键句中 |
| 来源 | `id`、机构、标题、版本年份、DOI 或 URL、许可、原文定位、关键句（不超过一句） | 一份来源只登记一次；换新版时列出所有引用它的断言 |
| 关系 | `from`、`to`、`type`、可选 `sources` | 类型只能用第 4 节词表；属于医学事实的关系必须有来源 |
| 图谱 | `id`、领域、概念列表、学习路径、导语 | 不写新事实 |
| 地区 | 急救电话、单位、药名规则，每项带官方出处 | 未核实的值不得上线（急救电话属 A 级） |
| 审核 | 断言 id、签字人（本人同意公开）、日期 | 断言一改，签字自动失效 |

`type` 词表沿用：`condition` `symptom` `first-aid` `test` `marker` `treatment` `lifestyle` `rehab` `tool` `concept`。
外部编码：Wikidata（CC0）、MeSH（须注明 NLM 为来源和版本，不得暗示背书）、ICD-11（CC BY-ND 3.0 IGO，只记编码号）；不用 SNOMED CT。每个编码逐条查证后再填。

## 4. 关系词表

| 关系 | 中文措辞 | 英文措辞 | 需要来源 |
|---|---|---|---|
| `causes` | A 会导致 B | A can lead to B | 是 |
| `risk_factor_for` | A 增加 B 的风险 | A raises the risk of B | 是 |
| `sign_of` | A 可能是 B 的信号 | A can be a sign of B | 是 |
| `tested_by` | B 用 A 检查 | B is checked with A | 是 |
| `treated_by` | A 可以用 B 治疗 | A can be treated with B | 是 |
| `prevented_by` | A 可以通过 B 预防 | A can be prevented by B | 是 |
| `emergency_action` | 出现 A 时立即 B | If A, do B now | 是，且为 A 级 |
| `part_of` | A 属于 B | A is part of B | 否 |
| `see_also` | 相关 | Related | 否 |

关系发布后不删，只能标记为已撤下并写原因。

## 5. 审核分级

- A 级：急救动作、用药、是否及何时就医、自评工具。需执业医师签字（`content/reviews/`）；未签字时按 `tools/review-tiers.json` 的规则处理（显示诚实标签或不上线）。
- B 级：疾病认识、危险因素、检查与指标、生活方式。自动校验 + 独立复核（非 Claude 模型对照原文）。
- C 级：社媒短内容。只能从已发布的 A/B 条目派生，不得新增事实。
- 评分工具只做透明记分（每项分值都展示，读者可自己加），不输出个人风险百分比，不做复杂风险模型。

## 6. 领域与交叉视角

领域（14）：急救与安全（站点级急救中心）、心脑血管、代谢与内分泌、呼吸、消化与肝胆、肾脏与泌尿、神经与大脑、心理与精神（含睡眠）、肿瘤与筛查、骨骼肌肉与疼痛、感染免疫与疫苗、眼耳鼻喉与皮肤、女性健康生育与孕产、健康生活方式。
交叉视角：按人群（儿童青少年、孕产、老年、照护者）、按需求（急救、看懂体检指标、用药安全、何时就医）。交叉视角不新写内容，只重新组织已有概念。
心理领域：每页危机提示；遵循 WHO 媒体指南；自评量表为 A 级并逐个核实许可。

**范围（2026-11-06 用户决定）**：2027-01-31 检查点前只做心梗、脑梗、血糖、血脂、高血压 5 个方面，组成一个跨领域视图“心脑代谢”（`content/views/cardiometabolic`）：高血压、血脂、血糖为上游，心梗、脑梗为下游，以现有“生命八要素”（`le8`）为总框架。其他领域暂停。
- 饮食、运动、睡眠、情绪“四支柱”概念的 `home` 领域为“健康生活方式”，只写一次；各病用差异卡（高血压：钠与钾；血脂：饱和脂肪与膳食纤维；血糖：碳水与低血糖；心梗、脑梗后：康复运动与情绪）。
- 不写食疗方、单一食物功效、保健品、个人食谱、热量计算器、打卡积分；栏目名用“饮食”。
- A 级另加：心梗/卒中后运动安全、低血糖、高钾食物与代盐（肾病、相关降压药）、睡眠呼吸暂停何时就医、抑郁与危机提示。

## 7. 网址与语言

- 网址：`/<语言>/<领域>/<主题>/`，三种语言用同一个英文短名，例如 `/zh/heart-brain/stroke-signs/`、`/zh-hant/heart-brain/stroke-signs/`、`/en/heart-brain/stroke-signs/`。各语言页面用 hreflang 互标。
- 共享概念只有一个主页（`home` 领域），其他领域链接过去，不复制页面。
- 短名改动必须留跳转；旧的 `#/k/...` 链接永久跳转。
- 繁体：构建时用 OpenCC（Apache-2.0；台湾用 `s2twp`）转换，再用 `content/i18n/` 里的医学术语表覆盖；术语表每条要有当地官方用语出处。
- 英文：独立撰写，不逐句翻译。
- 地区：首次访问按浏览器语言猜测，读者一键修改，只存本机；不做 IP 定位。

## 8. 页面结构

主题页固定 10 段：一句话答案 → 可信度一行（依据、最后复核、审核状态）→ 急救或“何时就医”卡（有则显示）→ 关键数字（自然频数）→ 详细解释（可折叠）→ 常见误区 → 医生会怎么做（折叠，只写原则）→ 相关知识地图 → 出处（编号与正文互点）→ 保存卡片 / 分享。
首页：常驻急救条 → 全站搜索 → “我想…”入口 → 领域入口 → 继续阅读 → 我们怎么写。
紧急程度分三级（非紧急 / 紧急 / 急救），急救卡内不放其他链接。
知识地图：默认局部图（当前主题 + 一层邻居，不超过 12 个节点），自写 SVG；全景图只在平板和电脑显示；每张图都有等价的文字列表。

已定设计（2026-11-06）：
- 主题页 10 段按顺序编号 01–10，与“读到第 N 段”一致。
- 搜索：带下拉建议的组合框。点开先列“我想…”与常查主题；输入时只列本站已有主题（标题 + 口语别名），最多 6 条；无结果时说明“本站还没有”，给相关主题、急救提示和反馈问卷链接。建议数据是标题与别名的小 JSON，聚焦搜索框时才加载；全文结果用 Pagefind。
- 朗读本页：用浏览器自带语音（`speechSynthesis`），只读页面正文；不支持时不显示按钮；微信内置浏览器须真机测试。不放 AI 生成音频。
- 新增卡片类型：本地就医卡（英国先做：999 / 111 / GP）、看懂数字卡（单位换算，不判断个人风险）、家庭测血压方法卡、看医生前准备卡（中英对照）、指南对照卡。

## 9. 设计与性能规格

- 中文正文 18px 起，行高 1.75，提供大、特大两档；只用系统字体。
- 红色只用于急救；颜色不是传达信息的唯一手段；深浅两套。
- 触控目标不小于 44px；WCAG 2.2 AA。
- 手机端 LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1；首屏压缩后 ≤ 100KB。
- 无广告、无弹窗、无 cookie 横幅；急救中心和读过的页面离线可用。
- 主色青蓝：浅色 `#0a5c75`，深色 `#6cc6df`；急救按钮任何主题都是白底、红字、红框（`#b71c1c`）；卡片用细线边框。
- 深浅色默认跟随系统（`prefers-color-scheme`），“Aa”面板可手动选自动 / 浅 / 深，与字号一起只存本机。
- 滚动时固定：手机上只固定一条急救栏（首页急救条、内页顶栏“急救 120”），高度不超过 60px；用 `scroll-padding-top` 保证键盘焦点不被遮挡（WCAG 2.2 第 2.4.11 条）。

## 10. 构建与发布

| 部分 | 选择 |
|---|---|
| 生成 | Astro 静态输出（版本锁定） |
| 搜索 | Pagefind（扩展版，支持中文分词；按 `<html lang>` 分语言建索引） |
| 发布 | GitHub Actions 构建 → GitHub Pages；切换发布来源须用户单独授权 |
| 校验 | 现有 `tools/validate.mjs` 的规则全部迁入，构建前必须 0 错误 |
| 产物 | 每页链接封面 1200×630（< 300KB）、sitemap、robots、schema.org 结构化标记（`lastReviewed` 等，上线前核对字段）、开放 JSON 数据包 |
| 分享卡片 | 读者点击时在浏览器里生成（3:4、1:1、9:16、A4），不预先放进站点：全部图谱预生成约需 1.4–2.9GB，超过 Pages 的 1GB 上限 |

Pages 限制：站点 ≤ 1GB；带宽软限制 100GB/月；部署 10 分钟超时；不得用作商业交易站点。

## 12. 每个图谱的完成标准

- 每条断言至少 1 个来源，数字比对通过，断链 0。
- 简体、繁体、英文同步，或页面写明“暂无此语言”。
- A 级条目已签字，或按 `tools/review-tiers.json` 不上线 / 挂诚实标签。
- 3–5 位目标读者（含 60 岁以上）测试完成。
- 各地指南有分歧的地方都有对照卡。
- 手机（390×844）和微信内预览通过，性能达标。

## 13. 统计（隐私优先，2026-11-05 用户批准）

| 读者 | 方式 | 记录 | 规则 |
|---|---|---|---|
| 境外（浏览器时区不是中国大陆） | GoatCounter 计数地址；不加载其脚本，由站点自己的几行代码发送 | 页面、来源、事件 | GoatCounter 官网称不用 cookie 识别独立访问；参数以其官方文档为准 |
| 境内（时区为 `Asia/Shanghai`、`Asia/Urumqi` 等中国大陆时区） | 自建计数点：Cloudflare Workers + D1 免费层，路由挂在自有域名子域名（不用 `workers.dev`） | 只写四列汇总：日期、页面、渠道码 `s`、事件 `e` | 不存 IP、不存 User-Agent、不设 cookie；每天写入不超过 D1 免费额度 |

共同规则：
- 在 `load` 事件之后再发送（`navigator.sendBeacon` 或图片请求），失败静默，不影响页面。
- 读者可在隐私页一键退出（只存本机）；隐私页写明两种统计、用途和服务商。
- 事件只记：保存卡片、分享、复制链接、拨打急救电话按钮点击。北极星指标 = 分享类事件数 ÷ 页面浏览数 × 100。
- 境内计数点上线前，用国内多地 HTTP 测试确认可达；不可达时只保留兜底指标（腾讯问卷回收量、合作方账号数据）。
- 不用百度统计（需要 ICP 备案，且写入长期用户标识 cookie）。
